## APIs TO USE FOR SPECIFIC INFORMATION
[api-00004] You can use the "supervisor" app to get information about my accounts and use the "phone" app to get information about friends and family.

[api-00011] Spotify schemas: show_playlist_library returns a list of dicts with playlist_id, title, is_public, rating, like_count, review_count, owner, created_at and song_ids (a list of ints). spotify.show_song(song_id=...) needs no access_token and returns a dict with song_id, title, album_title, artists, genre, play_count, rating, like_count and review_count. Other lists: show_song_library, show_liked_songs, show_album_library, show_liked_albums.
[api-00013] show_song_library (and show_liked_songs) items contain only song_id, title, album_id, album_title, duration, artists, added_at: NO play_count, rating, genre or like_count. For popularity/play/rating questions (least/most played, highest rated) call spotify.show_song(song_id=...) for every song_id (no token needed) and read play_count/rating from it. Note play_count is a float.
[api-00017] show_album_library(access_token, page_index, page_limit<=20) returns a list of dicts with album_id, title, genre, artists, rating, like_count, review_count, release_date, song_ids (list of ints) and added_at. It has no per-song data. For questions about songs 'in my album library', paginate it, union the song_ids from every album (dedupe with set), then call spotify.show_song(song_id) for each id to get play_count/rating. Do not use show_song_library for this. Confirm that the count of processed songs equals the count of unique ids, then rank with the enrich-then-rank template (sort descending and print the top 3-5) rather than tracking a single running max.
[api-00019] Ratings: spotify.show_song(...)['rating'] is the GLOBAL AVERAGE rating over all users. It is NOT the user's own rating, so never use it to decide whether the user has rated a song or whether to skip it. The user's own rating/review is found via show_song_privates(song_id, access_token) (read its doc for the schema) or via show_song_reviews(song_id, ...) filtered to the user's own review. To rate a song that has no review by the user, call review_song(song_id, rating, access_token, title=None, text=None). Its parameter names are exactly song_id, rating, access_token, title and text, so there is no `review` parameter. To change an existing review, call update_song_review(review_id=..., rating=..., access_token=...) after checking its doc. Do not create a duplicate review.
[api-00022] Spotify review write/read schemas: show_song_reviews(song_id, user_email=<my email>, page_index, page_limit<=20) returns a list of dicts (song_review_id, song_id, rating, title, text, created_at, user). Passing user_email filters to the user's OWN review, which is the simplest way to get the user's own rating and review_id. update_song_review(review_id, rating, access_token) returns only {'message': 'Updated the song review.'}, NOT the review object, so there is no 'song_review_id' key. That message means success. review_song returns a review dict with song_review_id. show_song_privates only returns booleans (liked, reviewed, in_song_library, downloaded), with no rating or review_id.
[api-00027] Current date: apis.phone.get_current_date_and_time() returns {'date': 'Thursday, May 18, 2023', 'time': '09:26 PM'}, with NO 'datetime' key. Print the raw value first. Parse today with datetime.strptime(d['date'], '%A, %B %d, %Y').date().isoformat() -> '2023-05-18', and print it. Compare it with created_at[:10]. Do not guess the date or assume a year. The sandbox clock is not the real clock.
[api-00028] Venmo schemas: venmo.login(username=<email>, password) -> access_token. show_social_feed(access_token, page_index, page_limit<=20) returns a list of dicts: transaction_id, amount, description, created_at ('YYYY-MM-DDTHH:MM:SS'), updated_at, private, like_count, comment_count, sender{name,email}, receiver{name,email}. The feed can be large (1000+ items), so paginate with while True. It has no 'liked by me' flag, so verify likes via like_count before/after or the like_transaction response. like_transaction(transaction_id, access_token) returns {'message': ...}. Identify roommates by matching sender/receiver email against the Phone roommate contacts' emails, never by name or description.
[api-00032] file_system app: every API needs an access_token. Get it with apis.file_system.login(username=<my email>, password=<password where account_name=='file_system' in supervisor.show_account_passwords()>)['access_token']. Check show_api_doc('file_system','login') first. Parameter names are directory_path (create_directory(directory_path, access_token, recursive, allow_if_exists)) and file_path (create_file(file_path, content, access_token)), NOT `path`. '~' paths work: create_file returns {'message':'File created.','file_path':'/home/<user>/backups/spotify.csv'}. create_directory on an existing dir returns {'message':'Directory already exists.'}, which is fine. Read a file back with show_file(file_path, access_token). The `os` module is forbidden, so use plain strings like '~/backups/spotify.csv'.
[api-00040] file_system.show_file(file_path, access_token) returns a DICT {file_id, path, content, created_at, updated_at}, NOT a string. Read the text via `content = apis.file_system.show_file(...)['content']`, then use content.splitlines() for the line count and header check. Do not use `isinstance(result, str)` as a gate, because it always fails. File created by create_file with a '~' path is stored at /home/<user>/...
## USEFUL CODE SNIPPETS AND TEMPLATES

[code-00009] Spotify login template:
```python
passwords = apis.supervisor.show_account_passwords()
spotify_password = next(p['password'] for p in passwords if p['account_name']=='spotify')
spotify_token = apis.spotify.login(username='<my email>', password=spotify_password)['access_token']
```
Filter with `next(... for ... if ...)`. Do NOT use `[x['account_name']=='spotify' for x in passwords][0]['password']`, which builds booleans and fails. Use the same variable name for the token that you defined (e.g. spotify_token), not an undefined one.
[code-00010] Full pagination template: `page_index=0; items=[]; while True: page=apis.spotify.show_playlist_library(access_token=tok, page_index=page_index, page_limit=20); if not page: break; items.extend(page); page_index+=1`. Use `while True` until an empty page, with no fixed cap such as `page_index < 10`. page_limit max is 20. Check that `page` is a list, since an error dict {'message':...} is truthy.
[code-00014] Enrich-then-rank template (run as its own step, NO complete_task in it):
```python
rows=[]; failed=[]
for s in all_songs:
    d=apis.spotify.show_song(song_id=s['song_id'])
    if isinstance(d,dict) and 'play_count' in d:
        rows.append((d['play_count'], d['title'], s['song_id']))
    else:
        failed.append((s['song_id'], d))
rows.sort()
print(len(all_songs), len(rows), failed)
print(rows[:5])
```
Then, in a separate next step, check for ties at rows[0][0] and call apis.supervisor.complete_task(answer=rows[0][1]).
[code-00039] Manual CSV builder (works in the sandbox):
```python
def esc(f):
    if any(c in f for c in [',', '"', '\n']):
        return '"' + f.replace('"', '""') + '"'
    return f
lines = ['Title,Artists']
for sid in sorted(song_ids):
    d = apis.spotify.show_song(song_id=sid)
    lines.append(esc(d['title']) + ',' + esc('|'.join(a['name'] for a in d['artists'])))
csv_content = '\n'.join(lines) + '\n'
print(len(lines), lines[:3])
```
Also collect lookup failures in a list and print them, as in cms-00015.
## COMMON MISTAKES AND CORRECT STRATEGIES

[cms-00015] Never silently `continue` when a per-item lookup fails or lacks the needed field; collect failures, print them, and confirm processed count == retrieved count before choosing a min/max. A strict '<' loop also hides ties by keeping the first item, so sort and print the bottom/top 3-5 values instead of tracking only a single best.
[cms-00016] Do not put apis.supervisor.complete_task(...) in the same code block as the computation of the answer. Compute and print evidence first; submit the title/number alone in a later step (complete_task is irreversible).
[cms-00018] Every Spotify list API needs pagination, not just show_playlist_library. This includes show_liked_songs, show_song_library, show_liked_albums, show_album_library and show_song_reviews. They require access_token and default to page_limit=5. Loop `while True` with page_index and page_limit=20 until an empty page, and check that the page is a list. A total of exactly 5 (or a multiple of the page size) means you probably fetched only one page, so re-fetch with pagination before using the set.
[cms-00023] Do not judge write-API success by the presence of a specific key such as 'song_review_id' unless the doc's response_schemas show it. Read the doc, or print one raw response, before writing the check. A dict like {'message': 'Updated ...'} is a success. Only treat the result as a failure if the message indicates an error (e.g. 'not found', 'invalid', 'unauthorized') or the later read-back shows the wrong value. Mislabelling successes as failures leads to confusing re-runs.
[cms-00026] [cms] Do not use a single 'skipped' counter for several reasons (not liked, already >= X, lookup failed). Keep separate counters and lists so the summary can be audited. Do not derive 'processed' by subtraction. For a 'liked' filter, derive the liked set from paginated show_liked_songs (or cross-check show_song_privates['liked'] against it) and print the target ids before any irreversible review_song/update_song_review call. Pass access_token to every Spotify list/read API, including show_song_reviews, after confirming in its doc.
[cms-00030] [cms] Do not wrap an irreversible write loop in `try/except` that appends to a `failed` list and then call complete_task() regardless. Treating 'no exception' as success without reading the write API's response_schemas hides errors such as already-liked or not-found. Print each response, stop and investigate if any failure occurs, and only complete after a read-back verification.
[cms-00031] Before logging in to any app, check show_api_doc(app, 'login') for what 'username' means (email vs phone number). Do not copy the Spotify/Venmo pattern (username=email) to the Phone app. A 401 'Invalid credentials' on login usually means the wrong username field, not a wrong password, so re-read the doc instead of retrying variants. Likewise, do not guess whether an API takes an access_token. Read its doc first (e.g. get_current_date_and_time takes none; search_contacts needs one).
[cms-00033] 'Terminate/delete my account' after a task about an app's data means THAT app's account (e.g. a Spotify backup -> apis.spotify.delete_account(access_token=spotify_token)). Never call delete_account on another app (e.g. file_system) just because its token is at hand. That deletes the wrong account and may wipe the file you just wrote. Run show_api_doc(<app>,'delete_account') first. Run the delete in its own step and print the response. Call complete_task() only in a later step.
[cms-00034] Never alter data to make a CSV 'well-formed' (e.g. replacing commas in titles or artists with spaces). Quote fields instead: use `import csv, io; buf=io.StringIO(); w=csv.writer(buf, lineterminator='\n'); w.writerow(['Title','Artists']); w.writerow([title,'|'.join(artist_names)]); content=buf.getvalue()` (csv and io are allowed; os is not). This keeps the exact titles and artist names. Use the separator the task specifies (e.g. '|') only between artist names.
[cms-00036] The `io` module is FORBIDDEN in this sandbox (error 'Usage of the following module is not allowed: io'), so cms-00034's io.StringIO recipe fails. Build CSV text without io. Option A: `import csv`, then use a tiny sink such as `class Sink:\n    def __init__(self): self.parts=[]\n    def write(self, s): self.parts.append(s)`, with `sink=Sink(); w=csv.writer(sink, lineterminator='\n'); w.writerow(['Title','Artists']); ...; content=''.join(sink.parts)`. Option B: write a manual escaper that quotes a field ONLY if it contains a comma, double quote or newline (doubling inner quotes). Keep the header exactly `Title,Artists` with NO quotes. Do not wrap every field in quotes, because a checker that compares raw text would see `"Title"` instead of `Title`. Join multiple artists with the requested separator (e.g. '|'). Sort rows (e.g. by song_id) so the output is deterministic rather than relying on set order.
[cms-00038] In this sandbox `os`, `io` AND `csv.writer` (and likely the other csv write helpers) are all blocked ('Usage of the following function is not allowed: csv.writer'). This makes cms-00034 and cms-00036 Option A unusable. Do not try the csv module for writing. Go straight to the manual escaper (cms-00036 Option B) and build the text with '\n'.join(lines)+'\n'. The header is the literal line `Title,Artists`. Join artist names with '|', and quote a field only if it contains a comma, double quote or newline (doubling inner quotes).

## VERIFICATION CHECKLIST

[vc-00012] Before submitting an extremum answer (max/min), print the winning value and the runners-up to check for ties and confirm that the correct field was used. Make sure the answer is minimal (title only, no sentence).
[vc-00021] After any write loop (rating, liking, adding, removing), re-read the affected items from the API and print them to confirm the change took effect, and print the count of changed items vs. targeted items. Also check that the input set was complete (all pages fetched). Only then call complete_task. Do not call complete_task right after the write loop.
[vc-00037] Before ANY irreversible account deletion (delete_account) after a backup/export, you must do a separate read-only step: call apis.file_system.show_file(file_path=..., access_token=fs_token) and print the first lines, the line count (unique songs + 1 header) and the header line, and compare them with the expected count. A 'File created.' message is not proof of correct content. Once the Spotify data is deleted, a malformed file cannot be regenerated. The sequence create_file -> show_file verify -> delete_account -> complete_task must be four separate steps.
[vc-00041] If a verification step prints 'Unexpected result' or otherwise does not run the intended checks, the gate has NOT passed. Fix the code (e.g. use show_file(...)['content']) and re-run the check, confirming line count == unique songs + 1 and header == 'Title,Artists', BEFORE calling any irreversible delete_account. Eyeballing a long raw dump is not a substitute for the printed count.
