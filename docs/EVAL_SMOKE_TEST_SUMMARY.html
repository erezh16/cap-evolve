AppWorld smoke test: cap-evolve vs ALTK-Evolve

Summary of the final results, run 13–14 October 2026. Results were first reported on issue #804.

In short
  • Both methods helped the AI agent on tasks it had never seen. ALTK-Evolve's gain is smaller and less certain.
  • cap-evolve improved it more: 53.6% of tasks solved, against 41.1% for ALTK-Evolve and 35.1% with no learning.
  • Caveat: during its training, cap-evolve broke an isolation rule. It looked at answers for some practice tasks, though never for the test tasks. So its lead over ALTK-Evolve may be partly unfair. See the reservation below.

What was tested

AppWorld is a public benchmark of everyday tasks, such as "pay back my roommates on Venmo" or "add the songs I liked this year to a playlist". The tasks run in simulated apps: music, payments, email, notes, a phone and others. An AI agent solves a task by writing Python code that calls the apps' APIs, step by step. A grader then checks the final state of the apps: did the right things change, and nothing else?

The agent under test was the open model gpt-oss-120b. Both methods try to improve it automatically, by learning from its attempts at practice tasks:

cap-evolve
Rewrites the agent's instructions and adds helper functions and API notes. In each round an AI assistant proposes changes, and a change is kept only if the practice score clearly improves.
ALTK-Evolve
Turns past attempts into written "lessons learned". It gives the agent the lessons most relevant to each new task.

Both methods used the same AI model (Claude Sonnet 5.5) to do the learning. Both learned from the same 147 practice tasks and were then scored on 168 test tasks that neither had seen. Each test task was run twice per method.

How to read these numbers

Task success
The share of test tasks the agent completed fully and correctly, averaged over the two runs.
Scenario success
The tasks come in groups of three variants of the same scenario. A scenario counts only if all three variants succeed, so this is a stricter measure of consistency.
95% range
The results vary from run to run, so the measured gain is an estimate. The true gain very likely lies inside this range. If the whole range is above zero, the gain is unlikely to be luck.

Reading the chart:

  • cap-evolve: its gain is clearly above zero on both measures.
  • ALTK-Evolve: its gain in scenario success is above zero. Its gain in task success (+6.0 points) is smaller, and its range starts just below zero, so on that measure the gain is not certain.
  • Head to head: cap-evolve solved 12.5 percentage points more tasks than ALTK-Evolve (95% range +3.9 to +21.4), subject to reservation 1.

Reservations

1. cap-evolve broke an isolation rule during training

To be fair, a learning method must only see whether each practice attempt passed, and which checks failed. It must never see the answers. cap-evolve's AI assistant can run shell commands on the machine. In its second training round, helper processes it started opened the answer files and reference solutions of some practice tasks. They also ran the official grader to test their own code.

What this does not affect: the test tasks were locked away the whole time, and a scan of every log found no access to them. The test score was not obtained by seeing test answers.

What it does affect: later rounds built on round 2's changes, which may include know-how taken from the practice answers. ALTK-Evolve had no such access. So cap-evolve's lead over ALTK-Evolve may be partly an unfair advantage. We added a lock for the later rounds. A clean re-run is needed to settle the comparison.

2. One run of each method

Each method trained once. Another training run could produce a better or worse result. These numbers describe the two trained agents, not the methods in general.

3. Unequal training effort

cap-evolve used about 1,030 practice attempts while training, and ALTK-Evolve about 150. This is how each method normally works, but the effort was not matched.

4. ALTK-Evolve had to run in its reduced mode

ALTK-Evolve produced 1,715 lessons. All together they would take about 83,000 tokens of text, about twice what this model can read at once (about 40,000 tokens). So it could only use its "retrieval" mode: 18 always-on lessons plus the 10 most relevant to each task. Published ALTK-Evolve results for this model used a different test setup, so they are not directly comparable.

5. Practice scores overstate real performance

cap-evolve solved 88% of its practice tasks, but only 53.6% of the new test tasks. It was tuned on the very tasks it was scored on during training, so its practice score is optimistic. Only the test scores above are a fair measure.

6. Results vary between runs

Running the same task twice gave a different outcome on roughly a quarter to a third of the tasks. That is why each task ran twice, and why the results are given with ranges.
