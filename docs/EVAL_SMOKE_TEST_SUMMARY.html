AppWorld smoke test: cap-evolve vs ALTK-Evolve

Summary of the final results, run 13–15 October 2026. Results were first reported on issue #804.

In short
  • Both methods made the AI agent better at tasks it had never seen.
  • cap-evolve improved it more: 57.1% of tasks solved, against 47.3% for ALTK-Evolve and 31.5% with no learning. The lead over ALTK-Evolve, about 10 points, is real but not large compared with the run-to-run noise.
  • A fair cap-evolve result took three training runs: in the first two, its AI assistant found answer material for practice tasks. These numbers come from the third run, which never saw any. See the reservations.

What was tested

AppWorld is a public benchmark of everyday tasks, such as "pay back my roommates on Venmo" or "add the songs I liked this year to a playlist". The tasks run in simulated apps: music, payments, email, notes, a phone and others. An AI agent solves a task by writing Python code that calls the apps' APIs, step by step. A grader then checks the final state of the apps: did the right things change, and nothing else?

The agent under test was the open model gpt-oss-120b. Both methods try to improve it automatically, by learning from its attempts at practice tasks:

cap-evolve
Rewrites the agent's instructions and adds helper functions and API notes. In each round an AI assistant proposes changes, and a change is kept only if the practice score clearly improves.
ALTK-Evolve
Turns past attempts into written "lessons learned". It gives the agent the lessons most relevant to each new task.

Both methods used the same AI model (Claude Sonnet 5.5) to do the learning. Both learned from the same 147 practice tasks and were then scored on 168 test tasks that neither had seen. Each test task was run twice per method.

How to read these numbers

Task success
The share of test tasks the agent completed fully and correctly, averaged over the two runs.
Scenario success
The tasks come in groups of three variants of the same scenario. A scenario counts only if all three variants succeed, so this is a stricter measure of consistency.
95% range
The results vary from run to run, so the measured gain is an estimate. The true gain very likely lies inside this range. If the whole range is above zero, the gain is unlikely to be luck.

Reading the chart:

  • Both methods: their gains are clearly above zero on both measures.
  • Head to head: cap-evolve solved 9.8 percentage points more tasks than ALTK-Evolve (95% range +1.2 to +18.5). The range only just stays above zero, so see reservation 2 before relying on the size of this gap. On scenario success the lead is clearer: +16.1 points (+6.2 to +25.9).

Reservations

1. Making cap-evolve's training fair took three runs

A fair learning method may only see whether each practice attempt passed and which checks failed, never the answers. cap-evolve's AI assistant can run shell commands on the machine, so we had to keep the answers out of its reach:

  • Run 1: its helper processes opened answer files of some practice tasks and ran the official grader. Result discarded.
  • Run 2: with the answers hidden, it found AppWorld's task-generator code for six practice scenarios, which shows how they are solved and checked. Result discarded.
  • Run 3 (the results above): answers, grader, task generators and test data were all hidden. A check of all 566 commands it ran confirms it touched none of them.

One remaining point: in run 3 it read the source code of AppWorld's simulated apps, that is, how the apps work inside. That is not answers, and it is the same for every task, but it is more than the public documentation the plan intended, and more than ALTK-Evolve had.

2. Results vary between runs

We ran the same baseline and ALTK-Evolve agents, unchanged, in two separate test runs. The baseline went from 35.1% to 31.5%, ALTK-Evolve from 41.1% to 47.3%. Results therefore move by several points between runs, even for identical agents. That is why all three methods were scored together in one run, and why a gap of about 10 points between two methods should be read with care.

3. One training run of each method

Each method's scored agent comes from one training run. Another run could produce a better or worse agent. These numbers describe the two trained agents, not the methods in general.

4. Unequal training effort

cap-evolve used 882 practice attempts while training, ALTK-Evolve 147. This is how each method normally works, but the effort was not matched.

5. ALTK-Evolve had to run in its reduced mode

ALTK-Evolve produced 1,715 lessons. All together they would take about 83,000 tokens of text, about twice what this model can read at once (about 40,000 tokens). So it could only use its "retrieval" mode: 18 always-on lessons plus the 10 most relevant to each task. Published ALTK-Evolve results for this model used a different test setup, so they are not directly comparable.

6. Practice scores overstate real performance

cap-evolve solved 78.9% of its practice tasks, but 57.1% of the new test tasks. It was tuned on the very tasks it was scored on during training, so its practice score is optimistic. Only the test scores above are a fair measure.
